# Specification: SortViz (Comparative Sorting Algorithm Visualizer)

## 1. Overview & Objective
SortViz is a web application inspired by [Toptal Sorting Algorithms](https://www.toptal.com/developers/sorting-algorithms), designed to visually animate and compare comparison-based sorting algorithms side-by-side on identical datasets. It is deployable as a static single-page application on Vercel and architected with a modular, generator-driven engine to enable AI agents to easily implement, test, and maintain individual sorting algorithms in total isolation.

---

## 2. Supported Algorithms
The application includes the 8 core comparison-based sorting algorithms from Toptal:
1. **Insertion Sort**: Incremental insertion into sorted prefix.
2. **Selection Sort**: Repeatedly finds the minimum element from unsorted suffix.
3. **Bubble Sort**: Adjacent element comparison and bubble-up.
4. **Shell Sort**: Diminishing increment gap sort (using Pratt or Knuth gap sequence).
5. **Merge Sort**: Divide-and-conquer recursive two-way merge.
6. **Heap Sort**: In-place binary max-heap construction and extraction.
7. **Quick Sort (Standard 2-Way)**: Divide-and-conquer partitioning (Lomuto or Hoare).
8. **Quick Sort (3-Way / Dutch National Flag)**: Dijkstra's 3-way partition (`< pivot`, `== pivot`, `> pivot`), demonstrating efficiency on duplicate keys.

### Selection Defaults & Constraints
- **Initial Load Selection**: Exactly 4 core algorithms enabled by default:
  - Insertion Sort
  - Selection Sort
  - Merge Sort
  - Quick Sort (Standard 2-Way)
- **Selection Control**: Multi-select pills/checkboxes allow adding or removing any of the 8 algorithms.
- **Constraint**: At least 1 algorithm must remain selected at all times (disabling the last checked box is blocked).

---

## 3. Dataset Configuration & Generation

### Array Size ($N$)
- Strictly powers of 2: $N = 2^k$ where $k \in \{3, 4, 5, 6, 7, 8\}$.
- Allowed values: $8, 16, 32, 64, 128, 256$.
- **Default on Load**: $N = 32$.

### Input Distribution Presets
All active visualizers receive the **exact same identical array** generated by one of 4 deterministic presets:
1. **Random**: Uniform random permutation of integers $\{1, 2, \dots, N\}$ (Fisher-Yates shuffle).
2. **Reversed**: Strictly decreasing sequence $[N, N-1, \dots, 2, 1]$.
3. **Almost Sorted**: Sorted sequence $[1, 2, \dots, N]$ perturbed with $\approx 5\%-10\%$ random adjacent element swaps.
4. **Few Unique**: Values drawn from 4 discrete value levels (e.g., $N/4, 2N/4, 3N/4, N$), uniformly distributed across the array.

### Constraints & Edge Cases
- No manual text array input is allowed.
- Generating a new array or switching presets resets all visualizer metrics, ranges, and bar states to initial baseline.

## 4. Visual Model & Divide-and-Conquer State Tracking (Requirement 4)

Each algorithm is rendered inside a distinct visualizer card. To clearly reveal algorithm mechanics beyond simple 2-pointer cursors, the visualization uses a dual-layer representation:

### A. Element Bar States
Each bar representing an array element has a distinct color token:
- **Default / Unsorted**: Neutral slate blue (`#64748b` / `--bar-default`).
- **Comparing**: Vivid amber/yellow (`#f59e0b` / `--bar-comparing`).
- **Swapping / Writing**: Vivid red/rose (`#ef4444` / `--bar-swapping`).
- **Pivot Element**: Bright cyan/sky (`#06b6d4` / `--bar-pivot`).
- **Locally Sorted / Merged Subarray**: Violet/purple (`#8b5cf6` / `--bar-locally-sorted`).
- **Globally Sorted**: Emerald green (`#10b981` / `--bar-sorted`).

### B. Subarray Range Trackers & Tinted Partition Bands
Above/around the bars, active partition boundaries and recursive ranges are explicitly marked:
- **Active Range Bracket**: A visual bracket or tinted background band enclosing indices $[L, R]$ currently processed by recursive or partitioning steps.
- **Partition Split Markers**: In Quick Sort / Quick 3-Way, distinct zone tints mark the boundary of subproblems (left partition, pivot zone, right partition).
- **Merge Buffers**: In Merge Sort, the left half $[L..M]$ and right half $[M+1..R]$ are distinctively tinted before and during the merge step into the auxiliary buffer.

## 5. Playback Engine, Synchronization & Runtime Controls

### Synchronization
- **Step-Synced Execution**: All active visualizers advance 1 discrete algorithm operation (comparison, swap, or range state transition) per animation tick in lockstep.
- This creates an immediate, intuitive visual contrast between $O(N \log N)$ and $O(N^2)$ complexities as faster algorithms finish earlier.

### Playback Controls
- **Play / Pause**: Starts continuous playback or pauses the global step clock. Playback proceeds continuously by default until all algorithms complete.
- **Pause at Every Step (Option)**: Toggleable checkbox. When enabled, clicking Play executes exactly 1 lockstep operation and automatically pauses for granular step inspection. When disabled (default), playback runs continuously.
- **Step Forward**: Manually advances exactly 1 step across all active visualizers.
- **Reset / Stop**: Halts execution, resets all algorithms to initial state (or regenerated baseline), and re-enables parameter controls.
- **Speed Slider**: Controls tick delay from Slow (e.g. 150ms/step) to Ultra-Fast (e.g. 1ms/step).

### Visualizer Metrics Display
Each algorithm card contains real-time counters:
- **Comparisons**: Count of element comparisons performed.
- **Swaps / Writes**: Count of element exchanges or direct array writes.
- **Operations (Steps)**: Total elapsed generator steps.
- **Status Chip**: Current state badge (`Idle`, `Running: Partitioning [L..R]`, `Running: Merging [L..R]`, `Completed`).

### Runtime Constraints & Edge Cases
1. **Algorithm Completion**:
   - When an algorithm finishes sorting while others are still running, its card transitions to **"Completed"** state.
   - All its bars illuminate in emerald green (`--bar-sorted`).
   - Its metrics freeze at their final values.
   - The global clock continues ticking until all active algorithms are finished.
2. **Controls Lockdown During Execution**:
   - While the animation is running (`Play` active), parameter controls ($N$ selector, distribution preset selector, algorithm toggle checkboxes) are **disabled**.
   - The user must click **Stop / Reset** to change configuration parameters.
3. **Empty Algorithm State**:
   - The UI enforces that at least 1 algorithm must remain enabled. Deselecting the last active checkbox is prevented.

## 6. Correctness Verification & Testing Strategy

### Automated Headless Tests (`vitest`)
Every sorting algorithm must pass an automated test suite verifying:
1. **Sorted Invariant**: For all algorithms across all 4 presets (Random, Reversed, Almost Sorted, Few Unique) and all $N \in \{8, 16, 32, 64, 128, 256\}$, the final array $A$ satisfies:
   $$\forall i \in [0, N-2], \quad A[i] \le A[i+1]$$
2. **Multiset Conservation (Permutation Check)**:
   The multiset of values in the final array matches the initial array exactly (no duplicated or lost elements).
3. **Generator Safety & Index Bounds**:
   Every yielded step event refers to valid array indices $0 \le \text{index} < N$.
4. **Graceful Completion**:
   Generators must terminate normally without infinite loops or uncaught exceptions.
